## Headline

Two things want fixing before the next release:

1. **An attachment someone sends you can run script in the app, and
   from there run any program.** The server decides whether a file it
   serves needs the `sandbox` policy by matching its content type
   against a short list. A type the list does not name but a browser
   renders as a page — `text/xsl`, or a comma list like
   `text/plain,text/html` — is served with no sandbox, in the app's
   origin, with the session cookie. Anyone can send an email part typed
   `text/xsl`. One click on the attachment, and the page can rewrite the
   config, whose step `command` runs any program (§1).
2. **The release trusts a branch and a tag that nothing guards.** The
   `main` ruleset lets the `everyone` team bypass it, and there is no
   rule on `v*` tags. Any of the 30 people with write access can push a
   tag on an unreviewed commit, and that tag's run signs, notarizes and
   publishes to `releases/latest`, which `install.sh` installs by
   default (§2).

The rest is the usual size for a fast-moving tree: one real SQL
injection behind an unusual input (§4), one panic that stops a source
for good (§5), and supply-chain loose ends that earlier audits named and
that are still open.

What held up well, checked rather than assumed: the search grammar never
puts a typed value into SQL; DOMPurify and the document frame's CSP close
the old stored-XSS path; the applet gateway forwards no cookie or token;
every archive unpack refuses `..`; every Bazel download, the runtime
fetch and the qmd models are pinned by sha256; `cargo deny` reports no
advisory.

## P1 — fix now

### 1. A served attachment can run script in the app's origin (High, verified)

**Fixed the same day**, in #1539: there is no list of dangerous types
any more. `set_data_headers` (`embed.rs`) sends
the sandbox policy on every `/data`, applet-proxy and remote-media
answer, a PDF alone excepted, and keeps a type only when it parses as
one type on a short list of shown ones, otherwise `application/octet-stream`.
`media_type` refuses a comma list. Quark's bar tab in the TNG mailbox is
a `text/xsl` attachment, and `document-sandbox.spec.ts` checks it runs
nothing as served, and that it does run with both guards turned off.

**Before (today).** `datalib/backend/http/src/embed.rs:198-214`
`is_scriptable_document` takes the content type up to the first `;`,
lowercases it, and sends `DATA_DOCUMENT_CSP` (`sandbox; default-src
'none' …`) only when the result is one of six HTML/XML types or ends in
`+xml`. Three routes use it: `/data/<group>/<fn>/blob/…`
(`data.rs:89-117`), the applet proxy (`lib.rs:525-541`) and
`/api/remote_media` (`remote_media.rs:446-470`). `is_executable`
(`embed.rs:177-194`) has the same shape.

Two kinds of type get past it:

- **`text/xsl`.** Browsers render it as an XML document, and an XHTML
  `<script>` in it runs. Checked in Chromium: a response typed
  `text/xsl; charset=utf-8` with `nosniff` ran its script.
- **A comma list.** Chromium and Firefox take the last type, WebKit
  the first. `text/plain,text/html` ran script in Chromium;
  `text/html,application/x-foo` ran script in a WKWebView, the engine
  the desktop app uses.

**Who can set the type.**

- **Email, anyone.** `blob_store/src/lib.rs:116-124` types a part as the
  message declares it, so a `text/xsl` part is served as
  `text/xsl; charset=utf-8`. Email attachments link to
  `/data/<group>/ingest/blob/<message>/part/<part>`
  (`etl/src/blob_cas.rs:1827`).
- **Signal and MMS**: the sender's declared type is stored verbatim
  (`signal/src/ingest/mod.rs:623`, `sms_backup_restore/src/ingest/parse.rs:215`).
  `sniff::content_type_for` (`etl/src/sniff.rs:28-36`) overrides a
  declared type only when the bytes carry image or PDF magic.
- **Remote media**: `media_type` (`remote_media.rs:184-196`) only checks
  `starts_with("image/")`, so `image/png,text/html` is stored.

**What it leads to.** chat-common draws a non-media attachment as a
link (`chat-common/src/render.rs:763-841`). `DocCard.ce.vue:80-91` opens
a same-origin link with `window.open`. In a browser that is a top-level
page on the app's origin with the cookie; `PUT /api/config` with a step
`command` is then code execution. In the desktop app, `on_new_window`
(`tauri/src/main.rs:976-983`) opens it as a card window, which matches
the remote capability and gets Tauri IPC (`withGlobalTauri: true`).

**Without a click, in a browser (likely, not run).** `fetch_policy`
(`auth.rs:97-106`) lets any site navigate to a GET URL with the Lax
cookie, and the default port is fixed. Its comment says that rests on
"every document served as data carrying its `sandbox` policy", which is
the premise this breaks. A whole-blob address is the blake3 of the
attacker's own bytes, so a sender who can guess the group id can link to
it. An email's address names the message as the server received it,
which the sender cannot predict; a Signal or MMS attachment's can be.

**After (the fix).** Send `DATA_DOCUMENT_CSP` on every response from
those three routes, whatever the type; it costs an image nothing. Then
turn the deny-list into an allow-list: serve inline only a single parsed
type known to be inert (image, audio, video, PDF, `text/plain`), and
everything else as `application/octet-stream` with
`Content-Disposition: attachment`. Refuse a stored type containing `,`.
A person notices nothing, except that an odd attachment downloads
instead of opening.

### 2. Nothing stops an unreviewed commit from being released (High, verified)

- The only ruleset, `main: CI green before merge` (id 22904358),
  requires two status checks and no review, and lists the `everyone`
  team as a bypass actor with `bypass_mode: always`. Classic branch
  protection is off. There is no tag ruleset.
- A `main` push runs `test.yml` with the release BuildBuddy org's write
  key (`test.yml:231-232`, `.bazelrc:215-219`), and the release replays
  that cache (`release.yml:237-244`).
- Any `v*` tag mints the Vault signing role (`release.yml:396-403`),
  signs and notarizes the dmg, publishes to `releases/latest`
  (`scripts/install.sh:95-96` installs it by default) and pushes
  `ghcr.io/…:latest` (`release.yml:775-776`).

**Fix.** Remove `everyone` from the bypass list; add a `pull_request`
rule with one approval; add a tag ruleset limiting `v*` creation to a
release team; put the signing step behind a GitHub Environment with
required reviewers. Nothing changes for a contributor who already merges
through PRs.

### 3. An unreviewed branch can replace the CI image (Medium, verified)

`devcontainer.yml:27-32,129-131` moves
`ghcr.io/imbue-ai/datalib_devcontainer:latest` on any `workflow_dispatch`
with `publish_latest: true`, from any branch. Every `main` run uses
`:latest` (`test.yml:208,394,592,652`), with the release-cache write key.
**Fix:** move `:latest` only when `GITHUB_REF` is a tag or
`refs/heads/main`; better, pin the image by a digest kept in the repo.

## P2 — real bugs with a narrower way in

### 4. Resetting a mirrored store runs a table name as SQL (Medium, verified)

`etl/src/doltlite_raw.rs:2022`: `format!("DELETE FROM \"{table}\"")`
with `table` from `sqlite_master` and no quote doubling. The sqlite_mirror
engine copies every table of a source file under its own name
(`sqlite_mirror/src/mirror.rs:68`, quoted correctly by
`plan::quote_ident`), so a Lightroom catalog, Photos library or Messages
database holding a table named `x"; DROP TABLE "sync_runs` lands intact.
`datalib-step --reset store` (`datalib_step/src/reset.rs:33`) then runs
it on a writer, and sqlx-sqlite executes every `;`-separated statement.
Confirmed in the sqlite3 shell. **Fix:** `.replace('"', "\"\"")`, as
`introspect.rs:207` already does.

Related, Low: `RESERVED_TABLES.contains(&name)` (`mirror.rs:79-81`) is
case-sensitive and SQLite names are not, so in append-only mode (beeper,
apple_messages) a source table `Problems` is upserted into the store's
own `problems` table. Confirmed with sqlite3. Use `eq_ignore_ascii_case`.

### 5. One photo with odd EXIF bytes stops every `media` sync (Medium, verified)

`media/src/ingest/meta.rs:328-332` checks `time.len() < 8` in bytes and
slices `&time[..8]`. `DateTimeOriginal = "2026:05:04 03:42:0\xff"`
becomes a `U+FFFD` across bytes 7-9 after `from_utf8_lossy`, and the
slice panics (confirmed by compiling the function). The scan has no
per-file panic isolation (`media/src/ingest/mod.rs:109,199`), the file
is never stored, so every run hits it again until someone deletes the
photo. **Fix:** `time.get(..8)?`. More broadly (Low): lopdf,
pdf-inspector, lofty and kamadak-exif all run inline on untrusted bytes
with no `catch_unwind` per file (`catch_unwind` appears once in the tree,
`etl/src/run_problems.rs:194`, per phase); one crashing file takes down
its whole source until removed.

### 6. Search can load an unpinned model (Medium, verified in code)

The search applet starts `provision_models` on a thread and serves at
once (`applets/src/unified_document_index/mod.rs:157-161`); a failure
only logs (`:258-277`). The query embedder spawns qmd with no
`models_present` check (`qmd_indexer/src/query_embedder.rs:86-102`;
only `Index::embed` checks, `qmd_indexer/src/lib.rs:427`). qmd fetches a
missing model from Hugging Face's `resolve/main`
(`third-party/qmd/src/llm.ts:352,1100-1102`) — the function's own
comment says so. A semantic search during the first 2 GB download, or
after a failed one, loads an unpinned GGUF. **Fix:** refuse to spawn the
embedder until `ensure_models` has returned Ok.

### 7. The shipped qmd runtime carries known critical advisories (Medium, verified)

`pnpm audit --prod` in `third-party/qmd/runtime`: 2 critical, 6 high, 1
moderate — `simple-git` ≤3.36 (via node-llama-cpp),
`@modelcontextprotocol/server` <2.3.0 (via `@tobilu/qmd`), `zod`.
Reachability is unclear (simple-git is the build-from-source path; we run
`qmd mcp` over stdio only, and the MCP advisories are mostly HTTP
transports), but this tree ships in the runtime asset, the app and the
image, and nothing in CI runs `pnpm audit`. **Fix:** bump or override,
and add `pnpm audit --prod --audit-level high` for the three shipped
trees to `test.yml`.

### 8. A message body still reaches our own origin through CSS (Medium, verified)

`ui/src/cards/remoteMedia.ts:82`'s `url(...)` regex misses a `)` inside
quotes, `image-set('…')`, and CSS escapes (`u\72l(`). Checked under
jsdom with the real DOMPurify and the options in `sanitize.ts`. The frame
CSP still blocks remote hosts, but an own-origin
`/api/remote_media?url=…&source=<id>` goes out with the cookie, and the
server trusts the caller's `source`/`document` to pick an allow row
(`remote_media.rs:290-334`): a read receipt that defeats image blocking.
`GET /api/remote_media` is also reachable by a cross-site navigation
(§1's `fetch_policy`), which can fill the disk 50 MB at a time. **Fix:**
drop a `style` that mentions `url`, `image-set` or `\`; make the fetch a
POST or refuse cross-site navigations on `/api/*`; derive the context on
the server.

### 9. The release still compiles third-party code with signing material loaded (Medium, verified, open since 2026-10-02)

`release.yml:537-549` exports the certificates; `build-signed-app.sh:116-131`
unlocks the keychain; only then does `pnpm exec tauri build` (:183)
compile the shell's whole dependency tree, build scripts and proc macros
included. `contents: write` and `packages: write` are workflow-wide
(`release.yml:33-35`), and no checkout sets `persist-credentials: false`.
**Fix:** a `cargo build --release --locked` of `datalib/tauri` before
the export; write permissions only on the upload jobs.

### 10. Records dropped with only a log line (Medium, verified)

AGENTS.md's rule is that a record we could not handle goes through
`problems`. These drop messages and tell nobody in the app:
`whatsapp_render/src/render/parse.rs:127,187,205,283,311` (then
`problems: Vec::new()` at :553); `signal_render/src/render/normalize.rs:35`
and `beeper_render/src/render/normalize.rs:49` skip a whole bucket;
`sms_backup_restore/src/ingest/mod.rs:161` marks an unknown XML file done
and never reads it again. Close behind: a stored payload that will not
parse reads as missing (`forge-ingest-common/src/lib.rs:824,832`,
`slack/src/ingest/db.rs:146`, `chatgpt/src/ingest/db.rs:62`,
`claude/src/ingest/db.rs:620`, `garmin_render/src/render/parse.rs:169-220`,
`applets/src/photos/mod.rs:225`).

### 11. Vulnerability alerting is half on (Medium, verified, open since 2026-10-02)

Dependabot security updates, secret scanning and push protection are
all disabled; the `cargo deny` job is not a required check;
`dependabot.yml:30-31` still says security fixes "still arrive as soon as
Dependabot sees them" — alerts do, PRs do not.

## P3 — Low

**SQL**

- `sqlite://{path}` URLs at 25 opens (`doltlite_raw.rs:514`,
  `pin/src/lib.rs:184`, `core/src/store.rs:13`, …) are percent-decoded
  and split at `?` by sqlx: a data root under `x%41y` opens a different
  file and the writer creates it there; one containing `?` fails every
  open. `pin::open_at` and `runtime/src/plain_sqlite.rs` already use
  `.filename()`.
- `changed_keys` (`doltlite_raw.rs:2851-2856`) puts primary-key column
  names unquoted into SQL; for a mirrored table they are the source's.
  Read-only pool.
- Table names minted from LinkedIn/Facebook export file names
  (`etl/files/src/export_files.rs:14-41`) go into SQL unquoted:
  `Order.csv` fails the whole ingest, and `problems.csv` lands on the
  store's own table.
- Free-text `LIKE` in `unified_document_index/src/db.rs:130-135` has no
  `ESCAPE`, so `%` and `_` are wildcards (bound, not injectable).

**Server and desktop shell**

- `/data/{group}/{function}/…` only checks that `function` does not start
  with `.` (`data.rs:43-47`); axum decodes `%2F` inside a segment, so
  `ingest%2F..%2F..%2Ftmp%2Fx` opens `/tmp/x/blobs.sqlite`. Token
  required, file name fixed.
- In the desktop app, `openExternal` falls back to `window.open`
  (`externalLinks.ts:74-88`), which `on_new_window` hands to the
  unscoped `opener().open_url` (`main.rs:976-983,1014-1018`): body links
  in `sms:`, `callto:`, `slack:` and other schemes DOMPurify allows
  launch an app, bypassing the JS scope in
  `capabilities/open-external-urls.json`.
- `<area href>` survives the sanitizer and `linkFromClick` only matches
  `a[href]` (`chatLink.ts:38`), so `target=_top` navigates the app tab.
- Still open from earlier audits: Tauri `"csp": null`,
  `withGlobalTauri: true`, any-port `127.0.0.1:*` in every remote
  capability, unknown schemes navigating in-app (`leaves_the_app`
  `_ => false`); `GET /api/config` returns the file's secrets
  (`lib.rs:962-964`); a pasted credential on latchkey's argv
  (`connect.rs:433-441,490-500,551-558`) and `scrub` missing
  `Authorization: Basic` and `user:pass`; the private-address guard
  missing NAT64, 6to4 and IPv4-compatible v6 and setting no
  `.no_proxy()`; the 401 page naming the data root.
- `request_log::record` sits outside the token gate and logs refusals at
  info (`lib.rs:318-319`): any web page can fill the run store.
- Every step and applet inherits the server's whole environment,
  `DATALIB_TOKEN` and `LATCHKEY_ENCRYPTION_KEY` included
  (`dag/src/subprocess.rs:209-249`, `http/src/applets.rs:84-119`).

**Ingest**

- Plain `curl` (`etl/web/src/http.rs:704-748`) runs without
  `--proto =https`, `-q` or `--url`, and no response is size-capped

  Drive revision export hands a raw `Location` header to it unchecked
  (`google_drive/src/ingest/api.rs:265-273`), so a `file://` redirect

- Signed URLs reach logs and stored error text: `HttpError` Display

- Export walkers follow folder links with no visited set and outside the

- No size or depth caps on unpacking: Takeout and Lightroom unpack to

- `handle/src/lib.rs:118` uses Unicode `to_lowercase()`, folding the

- Notion's `markdown_lite` (`notion_render/src/render/enhanced.rs:494-505`)
