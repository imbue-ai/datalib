# Audit: the reference docs against the tree, 2026-11-18

A dated record, not reference. The audit read every reference doc (the doc
map's docs, and the `README.md`, `INGEST.md` and `TRANSLATE.md` files beside
the code: 132 files) against the tree at `301359c0`, using the procedure in
[`style.md`](../style.md) §"Auditing the tree for drift and repetition".
What it found wrong it fixed in the same PR, #1869: about 90 files, names
that were gone, behaviour and counts that had moved, and repetition cut to
a link. **Re-checked 2026-11-27 at `ee03cb1b1`: 6 findings open, below,
and one answered.** Read the doc and the code before repeating one as
current.

## Answered since

- **`portable_search.rs` reserves the `qmd` and `qmd_vsearch` keys**
  (`datalib/backend/etl/macros/src/portable_search.rs:270`). They are
  still needed: both are older spellings of free text that a person may
  still type (`query.rs:136-140` in
  `datalib/backend/unified_grid_and_search_index/src/`, tested in
  `applets/src/unified_grid_and_search_index/search_tests.rs:276`), so no
  column may take either name. Retiring qmd's names elsewhere is #1767.

## Still open

- **`chipDragQuery` and a document.** `chipDragQuery`
  (`datalib/ui/src/cards/chipActions.ts:288-302`) says no search key names
  a document, and returns null for one, so a document chip drags as a link.
  Since #1825 `datalib_document_id:` does name one (`chips.md` says so).
  Dragging a document chip could write that search.
- **The plain-curl rules have no home but AGENTS.md** §"Auth (web API)":
  `HttpRequest::plain`, no `~/.curlrc`, https only, `max_bytes`. They
  belong in `latchkey.md` or a README beside `etl/web/`, which has none.
- **`docs/dev/fastmail.md`** is not on the doc map; `latchkey.md`,
  `email_download_modes.md` and the calendar and email `INGEST.md` files
  link it. It covers the credentials for Fastmail's email,
  calendar and contacts, so it reads as a section of `latchkey.md`.
- **`etl/sqlite_mirror/` has no README.** Five providers use the engine,
  and `lightroom/INGEST.md` is its de facto home.
- **`claude/INGEST.md` §"Bootstrapping from an export, then keeping it
  fresh with the API"** describes something it says is not built. It may
  belong in a plan.
- **`chat-common/README.md` §"Plain text is escaped; the UI sanitizes the
  rest"** still restates the reason that
  `data_architecture_parse_and_render.md` §"Upstream text is escaped where
  it becomes markup" gives (markdown rendered with HTML on, because the
  section wrappers are HTML), though it links there.
