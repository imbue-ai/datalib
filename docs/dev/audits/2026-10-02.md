# Audit: three weeks, 2026-09-11 to 2026-10-02

A record, not reference. It covers what landed on `main` between
`a8e82207d` and `034cdcf11`: 471 first-parent merges, roughly #423 to
#957, +309k/−156k lines, releases v0.34 to v0.39. Each change was read
for these problems:

- security, including what dependencies bring in;
- data and code architecture;
- fragile assumptions;
- copy-paste;
- tests that are fragile, under-specified or over-specified.

The read was against the rules in [`AGENTS.md`](/AGENTS.md) and
[`style.md`](../style.md). Line numbers are at `034cdcf11`.

This is a blameless review. It describes what the tree does and what
each change left behind, not who wrote it. Most findings are the kind
of gap a large, fast window produces: a rule the tree already states
that one new path does not follow yet.

**How it was read.** Eight read-only passes ran in parallel:

1. the UI refresh and containers layout (#942, #954, #955, #956);
2. the desktop shell, build and fetched binaries (#547, #953, #954, #955);
3. dependencies and CI supply chain;
4. the HTTP server's security surface;
5. the supervisor and sync loop;
6. data architecture;
7. duplication and rule violations;
8. test quality.

Each pass read the PR diffs and then the tree. The top finding of each
was re-read in the code a second time; those carry **checked**. Two
other labels appear: **read** means one reader traced the code path;
**plausible** means the path was read but the failure was not
reproduced. No tests were run for this audit. The supply-chain pass ran
`cargo deny` and `pnpm audit`, and read the repo's GitHub settings
through the API. CI flake history comes from `scripts/flaky_tests.py
--limit 400`. Earlier audits' items appear only where they are still
open.

**What was done about it.** #961 closed finding 1 and the P3 item on
the app CSP's `script-src 'self'`. Served data documents now run no
script; only a renderer's own plot pages do, and they have no network.
#964 then drew every document body in a frame whose policy runs no
script and keeps a sender's layout inside it. The dev launchers now
default to `~/Documents/Datalib/Default` rather than the `Datalib`
folder itself. That closes the dev half of finding 8; the move still
checks no lock. #997 and #1002 closed finding 5 and the CalDAV path of
finding 4: CalDAV and CardDAV share one sync-collection loop, a
listing deletes only once it reaches its end (in a later run if one
cut it short), and an expired CardDAV token lists the book again.
#1006 closed the rest of finding 4: Takeout's single-file feeds refuse
a file in a layout they do not know, a Google Calendar listing with an
event it cannot identify deletes nothing, and media keeps the rows of
files it found and did not read and deletes nothing after a walk error.

## P1 — wrong answers, lost data, or a hole someone can use

### 1. A synced message can run script, with network access, inside the app

A rendered document can contain an `<iframe>` whose `src` is one of our
own paths. `sanitize.ts:56-68` keeps any such iframe, and
`asset_urls.ts:44-50` rewrites a relative `blobs/…` path onto the
applet's asset route. The asset route serves HTML and SVG under
`DOCUMENT_SANDBOX_CSP` (`http/src/embed.rs:63`), which is only
`sandbox allow-scripts allow-downloads`. The sandbox takes away cookies
and same-origin access, but it sets no fetch directives. The parent
page's `img-src`/`connect-src 'self'` does not reach a framed document
that has its own URL.

Message text reaches markdown-it with `html: true` (a plain-text email
body, for example, gets only `autolink_bare_urls`). So a sender can
attach an HTML file and frame it from the body. When the message is
opened, its script runs and can reach the network: a read receipt
(which defeats the remote-image blocking of #655) or a convincing fake
prompt inside the app's own chrome.

Fix:
- Give framed documents a fetch policy along with the sandbox:
  `default-src 'none'`, inline scripts and styles,
  `img-src 'self' data: blob:`, `connect-src 'none'`,
  `form-action 'none'`.
- Plot pages load Plotly from a CDN; vendoring it removes the one
  remote origin they need.
- Narrow the iframe allowlist to the paths renderers actually emit
  (`plots/*.html`).
- Add a sanitizer test that a body iframe pointing at `blobs/` is
  stripped.

**Checked.**

### 2. Gmail label changes on mail already mirrored never reach the store

`gmail_api/mod.rs:371-389` sends both `added` and `relabeled` history
ids to `fetch_ids`. That function first skips every id in
`known_gmail_ids` (`:766`), which is meant to save quota on a re-walk. A
relabeled message is by definition already known, so it is always
skipped. Archiving, read/unread, starring, and adding or removing a
label never change the stored row. Only deleting or renaming a label
reaches it, through `refile_mailboxes`. The path predates the window;
9ffec77f1 (Sep 15) and #937 worked on it.
[`email_download_modes.md`](../email_download_modes.md):193 says
relabeled ids "are fetched".

Fix: apply the `labelIds` that `history.list` already returns for
relabeled ids, or exempt them from the known-id skip. Add a playback
test with a `labelsAdded` record, and watch it fail first. **Checked.**

### 3. A source removed from `grid_index`'s inputs keeps its rows in the grid

Every delete in `etl/render/src/grid_index.rs` is keyed by
`markdown_uuid` or by a listed `source_id`. None removes the sources
the inputs no longer name. A purge (`http/src/supervisor.rs:479-499`)
removes `<root>/<group>/` and leaves the index alone. So a deleted
source's documents stay in the search grid; opening one fails because
the `.md` is gone. Its problems keep counting, and the qmd index (which
does retire the collection) disagrees with the grid. That is personal
data a person believes they deleted.
[`config_model.md`](../config_model.md):260 says the source "stops being
indexed on the next run". The one test (`only_the_listed_sources_are_read`)
starts from an empty index.

Fix: at the start of each pass, inside the sealed transaction, delete
every index row and `source_cursors` row whose `source_id` is not
listed. Add a test that indexes a source, unlists it, and asserts the
rows are gone. **Checked.**

### 4. Deletion passes that do not prove the listing was complete

The window added delete-on-rescan to several sources (#907, #910, #913,
#757). The rule from the earlier Garmin finding
([`2026-09-18.md`](2026-09-18.md) §1) is that only a complete
enumeration may prune. These paths do not check it:

- **CalDAV** (`calendar/src/ingest/caldav/mod.rs:242-292`). With no
  token, the loop follows 507-truncated replies for up to 50 rounds,
  and also stops when the token does not move. `drop_unlisted` then
  runs whatever state the listing ended in. `list_whole` and
  `list_window` (`:300-337`) prune without a 507 check. A large
  calendar, or a server that pages without moving its token, loses
  every event not reached. **Checked.**
- **Takeout single-file feeds.** `youtube_watch_history.rs`,
  `youtube_subscriptions.rs` and `gemini_apps.rs` always return
  `Some(rows)`. A newer export's layout that parses to zero rows then
  prunes the whole table. The provider README promises `None` in that
  case; only the two Maps parsers do it. **Read.**
- **Google Calendar** (`calendar/src/ingest/google.rs:248-251`). An
  event `GoogleEventRow::new` cannot build is left out of the seen set,
  so a full listing deletes the stored copy with no problem row.
  **Read.**
- **media** (`media/src/ingest/mod.rs:229-238`). This predates the
  window. The reconcile deletes every cached path the walk did not
  visit, ignoring `scan.errors`, iCloud-evicted (dataless) files and
  files over `max_bytes`. **Read.**

Fix: make "the listing is complete" a value each walk returns, and
prune only on it. Return `None` from a parser that finds nothing in a
non-empty file, and refuse a prune that would take every row. Count
vetoed and oversize files as seen. Each path needs a test where the
listing is cut short.

### 5. CardDAV: an expired sync token freezes the address book with no sign

`contacts/src/ingest/mod.rs:241-261` treats 403, 405 and 501 as
"sync-collection unsupported". It logs that it is "walking whole", a
fallback that does not exist, and returns `Ok(())`. RFC 6578 answers an
expired token with 403. The stored token is kept, so that address book
never syncs again, and nothing reaches the Manage screen. CalDAV
handles the same case correctly (`caldav/mod.rs:247-255`): it clears
the token and lists again.

The CardDAV path also writes no problem rows for a failed book or a
vCard with no UID. Fix: do what CalDAV does, and report through
`download_problems`. **Checked.**

### 6. Email keys changed meaning without a ladder rung (#884), and mbox can prune API rows

#884 keyed Gmail rows by Gmail's own id. The schema guard compares only
table shape, so an old store opens without complaint.

- **Gmail-API stores.** Old rows keep their Message-ID keys forever,
  because `fetch_ids` skips known ids, leaving two key spaces in one
  table. `destroy()` (`gmail_api/mod.rs:989`) deleting one message of a
  pair that collapsed onto one Message-ID removes the row the other
  still needs.
- **mbox stores.** These re-key only on a full re-read, and each re-key
  changes the grid uuid, which orphans feedback filed against the
  email.

#884 also makes Takeout and API rows share keys on purpose. But
`mbox.rs:413-417` prunes the account on any clean `read_all`, and the
first run against an empty mbox cursor is one. Switching a live Gmail
source to `mbox` to backfill from an older Takeout therefore deletes
every email newer than the export. The only signal is a `prune_large`
`warn!`.

Fix:
- Add a rung to `schema_raw::LADDER` that re-keys through
  `gmail_messages`, which holds both ids. At minimum, add a rung that
  refuses to open and names the reset.
- Have mbox prune only when `may_have_dropped_records()`, and only rows
  it wrote itself (a provenance column or a per-scope seen set).

**Read.**

### 7. A quick restart can run a second copy of a step that is still stopping

On shutdown, `http/src/main.rs:174-191` gives the loop `SYNC_STOP_WAIT`
(2 s). It then calls `std::process::exit(0)` with steps still
checkpointing, and the 15 s SIGKILL rung in `subprocess.rs` dies with
the process. On the next boot, `host.rs:179-201` `take_over` marks the
old invocations stopped without checking whether they are alive (the
`invocations` table records no pid or pgid). The open requests then
start those steps at once.

Quitting the app mid-sync and reopening it quickly therefore puts two
copies of a step on one store. A custom `command` step that ignores
SIGINT and does not watch `DATALIB_PARENT_PIPE` is never killed at all.
[`dag/README.md`](/datalib/backend/dag/README.md):418-420 promises a
step "cannot hold its store for good".

Fix: record each invocation's pgid and process start time. In
`take_over`, wait out or signal any group still alive before serving.
The start time guards against pid reuse. **Checked** (the exit path);
the collision is plausible.

### 8. "Move into Default" can rename a live library, and the dev launchers set up the case it handles

The libraries screen (#954) offers to move a library that sits at
`~/Documents/Datalib` itself into `Datalib/Default`
(`tauri/src/launcher.rs:104-134`). The only guard
(`tauri/src/main.rs:80-94`) is that this app has no library open.
Nothing tries the root's `system/lock` or `system/runner-lock`.

`datalib/dev.sh:111` and `serve_dev.sh:78` default the root to
`~/Documents/datalib`. On macOS's default case-insensitive APFS that is
the same folder. Running the dev server with no argument therefore
makes the libraries folder a "legacy" library. The app then refuses to
create new libraries and offers the move. If pressed while that server,
or a step still stopping, is live, the move renames stores mid-write,
and the next open recreates them at the old path. If the folder already
held other libraries, they end up nested under `Default/`.

The move itself also cannot recover from a failure:
- it renames entries while iterating `read_dir` on the same directory;
- it has no rollback;
- one failed rename can leave `config.toml` inside the hidden
  `.Default-moving` folder, so the library disappears from the screen
  and a retry fails with `AlreadyExists`.

Fix:
- Try-lock both lock files before moving, and refuse if either is held.
- Collect the entries first, roll back on error, and treat a leftover
  `.Default-moving` as a move to resume.
- Move the dev default root out of `~/Documents` and update
  [`first_time_dev.md`](../first_time_dev.md):130.

**Checked.**

### 9. A failed read of the saved layout overwrites it

#956 keeps the containers layout in the library, at
`system/ui-state/layout.json`. In `ContainersView.vue:199-230`, a failed
GET makes `readKept` toast "starting afresh" and return null. `start()`
then builds a fresh Dashboard tree and sets `ready`. The save watcher
(`:148-152`) PUTs that tree over the stored file 400 ms later. If
`parseTree` rejects one node, say a layout name a newer build wrote, the
whole tree is null and is overwritten with no toast.
`composites.ts:51-57` does the same to saved composites when their load
fails.

Two more things can feed this:
- every PUT for a name shares one temp file (`ui_state.rs:77-82`), so
  two overlapping saves can tear the JSON;
- the "main window" Web Lock coordinates only one browser profile, and
  `ui/scripts/render.mjs`, which the agent cards guide tells agents to
  run, writes the person's layout as a main window.

Fix:
- Save nothing until a read has succeeded.
- Move an unreadable file aside (`layout.unreadable.json`) and say so.
- Give each write a unique temp name.
- Add a version or `If-Match` to `/api/ui/state`.
- Have `render.mjs` set `datalib-layout-unsaved`.
- Pull `start()`'s decision out as a pure, tested function.

**Checked.**

## P2 — fragile, or quietly wrong

### 10. Whole feeds fail with only a `warn!`

`google_takeout/src/ingest/mod.rs:141-252` has eight copies of
`Err(e) => { warn!(…); summary.parse_errors += 1 }`. The same function
builds `problems` and calls `report_run` at `:252`. So a whole Takeout
product can drop out with nothing on the Manage screen. The same shape
appears in:
- linkedin (`ingest/mod.rs:170,190,222`) and facebook (`:171`), both
  added in the window;
- `agent_sessions/src/lib.rs:133`;
- airvisual (7 `warn!`, 0 problems);
- `whatsapp_render/src/render/parse.rs:124+`.

AGENTS.md §"Fallbacks" says a `warn!` alone reaches nobody. Fix: push a
`RunProblem` per failed feed, file or CSV, and fold Takeout's arms into
one table of `(name, enabled, ingest fn)`.

### 11. Supervisor error paths

- **A store error mid-sync kills without stopping.** Every store call
  in `round.rs::serve` uses `?` (`:528, 550, 554, 565, 603, 619, 623`).
  An `Err` drops the `JoinSet`. tokio's `kill_on_drop` SIGKILLs only
  the leader pid, so qmd's node grandchild lives on, and the stop task
  waits forever (`step.rs:349-357`). One reader holding a transaction on
  `supervisor.sqlite` for 10 s is enough to trigger it. Treat a failed
  save as retryable, and on a fatal error drain through the stop
  ladder.
- **The server's loop can give up silently.**
  `http/src/supervisor.rs:190-203` returns for good when
  `Store::open`, or the lock (for a reason other than "held"), fails.
  The UI keeps accepting `POST /api/requests` for work nobody will
  serve. `fail_open_requests` (`:424-433`) swallows its own errors.
  Report "the loop is not running" through `/api/dag` or `app_ready`,
  and retry with backoff.
- **`datalib-dag` keeps serving everyone's syncs after its own request
  ends.** `serve` returns only when every open request is closed
  (`round.rs:567-574`). So `datalib-dag --sync x && next` can wait for
  hours. A second Ctrl-C SIGKILLs every step with no grace. The usage
  text (`datalib_dag.rs:72-73`) says it "exits with the request's
  outcome". Fix: cancel the loop once the CLI's own request closes.
- **A follower can wait forever.** With no server up, a follower
  `datalib-dag` waits forever after the lock holder is SIGKILLed. The
  release is announced only from `Drop` (`lock.rs:21-26`), and the
  backstop wakes only when the store changed. Retry
  `try_acquire_runner` on each backstop wake.

**Read.**

### 12. Lock-model edges

- **Naming a lock drops a qmd step's safety lock.** Naming any lock on
  a qmd step drops its built-in `qmd_embed`/`qmd_keyword` lock
  (`locks.rs:105-110`, `config.rs:1508-1520`). `locks.rs:63-68` says
  two embeds race on qmd's vector table. Make correctness locks
  additive and only budget locks replaceable.
- **A running step's locks come from the new config.** After a swap,
  `tick.rs:199-206` counts a running step's locks from the new config,
  not the definition it started with. Keep the starting locks in
  `Live`/`Running`.

**Read.**

### 13. `serve` is a 488-line loop that still makes policy decisions

`round.rs:201-688` decides these inside the async shell, between
awaits:
- whether a config swap may happen;
- carry-over;
- settling, and when to emit `PassEnd` and `finish`;
- which requests a step serves;
- the order requests close in.

This is the open half of [`2026-09-21_fcis.md`](2026-09-21_fcis.md)
finding 1. `tick.rs` shows the target shape. Extract pure
`settle(graph, tick, slots)` and `swap_plan(current, next, running,
roots)`, and unit-test them like `tick`.

### 14. Search, removal and the qmd index disagree

- **Removing the aggregator does not turn search off.** The applet
  decides whether qmd search is on from whether the index file exists
  (`applets/src/unified_index/mod.rs:658`). The file stays in the
  `unified_index` tree when `qmd_aggregator` is removed, so free-text
  search keeps answering from a frozen index. `AGENTS.md`:250 and
  [`config_model.md`](../config_model.md):279 say removing it turns
  search off. Fix: the applet reads the config.
- **The search card splits quoted filters apart.** `cards/search.ts:21-40`
  (#942) splits on whitespace and moves every `key:` word to the front.
  `hello source_name:"Slack work"` becomes
  `source_name:"Slack hello work"`. A typed filter comes from a person,
  which AGENTS.md asks us to treat with care. Fix: reuse the grid's
  quote-aware grammar (`grid/query.ts`, `datalib_query`) instead of a
  second parser. **Checked.**

### 15. Write paths outside the doltlite rules

- **The standalone fsindex binary commits without publishing.**
  `datalib-fsindex` commits on `datalib_writer` and never calls
  `publish_to_main` (`fsindex/src/bin/fsindex.rs:121`), so
  `datalib-dirtree-diff` reads the previous scan. Its `--branch` help
  text is now wrong too.
- **The blob CAS conversion (#891) has no lock of its own.**
  `copy_doltlite_cas` deletes any existing `.sqlite.tmp`
  (`blob_cas.rs:140-145`). That is safe only because every caller
  already holds the entities lock.
- **A render can run before the conversion.** On an upgraded root, a
  render that runs before the first ingest finds no `blobs.sqlite` and
  writes "not fetched" placeholders. Incremental renders never revisit
  those documents.
- **Pools are dropped instead of closed** on several `?` paths after
  `connect_pool` (`open_inner`, `CasEntityStore::open_migrating`,
  `read_source`).
- **Two reader statements are not on the two-process allowlist:**
  `PRAGMA table_xinfo` and `pragma_function_list`.
- **`embedding_map` reads without a transaction.** It reads qmd's
  SQLite in six statements, with no read transaction, while an `embed`
  step may be writing it.

### 16. Fetch problems go stale or briefly vanish

- **Pruned records keep their problems.** `prune.rs` deletes a record
  and its sidecar, but not its `problems` row. Only a successful fetch
  clears that row, and that can no longer happen.
- **Fetch problems vanish during a render.** `put_entity_problems`
  (`indexed_markdown.rs:867-927`) deletes entity-scoped rows by table
  prefix with no stage filter. Fetch problems are therefore missing at
  every render checkpoint, and after a failed render, until
  `carry_fetch_problems` runs.

Fix: delete the problems row in the record's own transaction, and
filter by `stage`.

### 17. The desktop shell is not compiled on PRs

`test.yml` runs only `cargo deny` on `datalib/tauri`. Bazel tests only
`launcher.rs` and `raw_store.rs`, and `main.rs` is built only by
`release.yml`. About 400 changed lines go untested and uncompiled on
PRs: the move guard, `open_folder`, library switching. #955 moved
`urlpattern` from 0.3 to 0.6. That crate decides which origins get IPC,
and the capability files warn that a mismatch fails silently.

Fix: add a PR job that runs `cargo check` and `clippy` on
`datalib/tauri`. Move the guards into `launcher.rs` as pure functions.
Have `check-app.sh` invoke one remotely-granted command.

### 18. Desktop shell edges

- **Switching libraries SIGKILLs the server.** Switching or closing a
  library calls `kill()` on `datalib-http` (`main.rs:276-285`), though
  the server shuts down gracefully on SIGTERM or parent-pipe EOF. The
  2026-09-17 audit flagged this for app exit; it now happens on every
  switch.
- **Any folder can be adopted as a library.** "Open a folder…" skips
  `classify`. `is_data_root` (`launcher.rs:168-170`) accepts a folder
  with a `system/` directory, which on case-insensitive APFS matches
  macOS's `System`. Require `config.toml`, or `system/` with a datalib
  marker file.
- **Libraries live under `~/Documents`.** That folder is often synced
  by iCloud "Desktop & Documents" or Dropbox, which continuously upload
  and can evict gigabyte-sized stores. This is a product decision;
  record it, or warn when Documents is cloud-backed.
- **Smaller items:**
  - the launcher's Tauri commands run on the main thread, so a stale
    network mount freezes the app;
  - `library-summary.json` is written from a GET handler through one
    shared temp name;
  - `launcher_create` makes the root 0755 before `create_data_root` can
    apply 0700.

### 19. The Dashboard copies the Sources card's row actions

`cards/useDashboard.ts:92-132` re-implements sync, stop, `openLog` and
`openProblems` from `cards/rowActions.ts`, and the copies already
differ: the Dashboard's log always jumps to the end, and its problems
grid has no placeholder. [`cards.md`](../cards.md):477 says rowActions
is shared with the dashboard. Each of the five section cards calls
`useDashboard` itself, so every `manage.rows` frame causes five parallel
fetches. Share one composable and one rows store.

## P3 — security hardening

- **Remote-media context comes from the caller.** A body's
  `<img src="/api/remote_media?url=…&source=<other>">` is an own path to
  the sanitizer (`remoteMedia.ts:31-33`), and the server trusts the
  context the caller names (`remote_media.rs:13-19, 290-312`). So one
  source's allow rows can cover another source's tracker. Drop own-path
  `/api/` URLs from bodies, and treat a leading `/\` as remote.
- **The app CSP's `script-src 'self'` covers files a sender controls.**
  The asset route serves a `.js` attachment as `text/javascript` from
  our own origin, with no sandbox (`embed.rs:42-55`,
  `unified_index/mod.rs:1031-1036`). Never serve an executable type
  from the asset route or the proxy, and send the sandbox CSP on every
  proxied response.
- **A pasted credential is on `latchkey`'s argv (#872).** Another local
  user can read it with `ps` (`connect.rs:254-337`). `scrub()` misses
  `Basic …` and `user:pass`. Add stdin or env input upstream.
- **Bodiless POSTs can be forged from another local port.** Stop,
  turn-off and turn-on take no JSON. Every 127.0.0.1 port is the same
  site to SameSite, so a page on another local port can post them.
  Check `Origin` or `Sec-Fetch-Site` on unsafe methods in
  `require_token`.
- **The private-address guard has gaps.** `is_public_v6`
  (`remote_media.rs:147-162`) misses IPv4-compatible, NAT64 and 6to4
  forms. A set `HTTP(S)_PROXY` bypasses the DNS pinning; build the
  client with `.no_proxy()`.
- **Still open from 2026-09-17:**
  - `GET /api/config` returns secrets;
  - `?token=` is accepted on `/api/*`;
  - the 401 page names the data root's path;
  - remote Tauri capabilities match every `localhost:*` port, and
    `leaves_the_app` lets unknown schemes navigate inside the app.

## P3 — supply chain and CI

- **Vulnerability checks are not enforced.**
  - The `cargo deny` job is not a required check.
  - Dependabot security updates and the dependency graph are off.
  - Secret scanning and push protection are off.
  - No `pnpm audit` runs anywhere.
  - `.github/dependabot.yml`:27-28 says advisories "still arrive as
    soon as Dependabot sees them", which is not so as configured.

  Make `cargo deny` required, turn the settings on, and add
  `pnpm audit --prod` for `datalib/ui` and the vendored runtimes.
- **latchkey 3.15 loads plugins.** It imports every module under
  `~/.latchkey/plugins/` on start, with no opt-out (`dist/src/plugins.js`,
  called from `cliCommands.js:44`). That is the process holding
  decrypted credentials, shipped under our signing identity. The pin
  bump checked only that the CLI output still parses. Ask upstream for
  a disable switch and set it. Until then, warn when the directory is
  non-empty, and add "new code-loading or network surface?" to the
  bump checklist.
- **Some images are referenced by mutable tag.** `moby/buildkit:latest`
  in the release docker job (`release.yml:742`) and `FROM ubuntu:26.04`
  are tags, not digests. Two Dockerfile comments still say 24.04. Pin
  both by digest.
- **Release jobs hold write tokens while running third-party build
  code.** `contents: write` and `packages: write` are set at workflow
  level, every checkout persists its credentials while every crate's
  `build.rs` runs, and `build-signed-app.sh` unlocks the signing
  keychain before compiling the Tauri lockfile. Set per-job permissions
  and `persist-credentials: false`, and sign the finished bundle.
- **The curl shims (#547) are verified only by hand.** They are
  sha256-pinned and built and attested in our org's CI, which is the
  right shape. But `gh attestation verify` ran only when the sums were
  written. The router (which now also routes through a desktop proxy)

## What the window improved

- **Security.**
  - Applets require a per-spawn secret plus a `Host` check, and the
    applet proxy refuses CR/LF in its targets.
  - DOMPurify sits behind an app CSP with `frame-ancestors 'none'`, and
    DACTAL is sandboxed.
  - The server alone judges remote media, pinning DNS on each hop.
  - Grid cells never render HTML.
  - Every client sort, group and filter key resolves to an enum, and
    every value is bound.
- **Supply chain.**
  - Every GitHub Action is pinned by SHA; none were before.
  - A `cargo deny` job exists.
  - Runtime fetches (Node, qmd GGUFs, the perseus model) are
    sha256-pinned and re-verified, and `npx` is opt-in and loud.
  - BoringSSL/wreq left the tree, and AG Grid Enterprise was replaced
    by MIT SlickGrid.
  - The curl shims come from attested, pinned builds.
- **The supervisor's tick is a functional core.** `tick.rs` takes facts
  and returns decisions with no clock or I/O, and is backed by about
  600 lines of pure tests. The loop never opens a step's output (#811).
  `datalib-http` links nothing from etl or unified_index.
- **Announcements replace polling** (#779, #793). The backstop counts
  its own misses, so a lost announcement fails a test instead of adding
  latency.
- **A concurrency harness** (#786, #879): puppet steps plus a seeded
  walk. Every race it found has a deterministic regression test that
  names its seed.
- **Doltlite discipline.**
  - Writers work on `datalib_writer`, with a read-back check.
  - Detached `<store>@<hash>` readers replaced about 640 lines of
    pinned views.
  - Every engine fact is a named test (#893).
  - Recycling is off on every pool, and a lint enforces it (#761).
- **Schema safety.**
  - A non-additive change refuses instead of dropping data.
  - There is a resumable migration ladder and a downgrade guard.
  - `_datalib_meta` names the build that wrote each store.
- **Deletions propagate** for file-backed sources, with walk-error
  hold-backs. #907's guard tests were watched failing without the
  guard.
- **Problems** travel raw → render → index and show on the Manage row
  and above the document.
- **Search and grid.**
  - Paged, server-sorted, server-grouped grids.
  - One-pass `grid_index`.
  - Per-source keyword and embed steps, so embedding can be turned off.
  - Search keys declared on the schema, with a test that each one is
    indexed.
- **Less code.**
  - #802 shared provider code (+5.0k/−7.7k).
  - #812 shared the email and Slack playback setup.
  - #760 gave calendar and contacts one WebDAV client.
  - #956 replaced four layouts with one (net −1.5k), with its rules as
    pure functions and 200+ lines of tests.
  - #942 extracted the Sources card's logic rather than copying it.
  - The library launcher is a pure, Bazel-tested `launcher.rs`.
- **Test hygiene.**
  - Sleeps were replaced by flushes and barriers (#783).
  - Integration tests link once per package (#665, #705), with the
    shared-process hazards fixed (#689).
  - `testing.md` gained "Writing a spec that does not flake".
  - The TNG fixture is built through `datalib-http`'s API (#770).
  - `/metrics` has a real scrape test (#939).
  - The Queue/ETA logic is pure, with eight tests (#935).
